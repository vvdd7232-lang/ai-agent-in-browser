# RelayBridge

**RelayBridge** — нативный Windows `.exe` на C++, который превращает обычный чат с ИИ в помощника с доступом к локальному терминалу.

Идея простая: модель в браузере сама терминал не видит. RelayBridge даёт ей строгий протокол: модель возвращает специальную команду, пользователь копирует ответ, программа запускает `cmd.exe` в выбранной папке и сразу кладёт результат обратно в буфер. Результат остаётся только вставить в чат — и модель продолжает задачу, уже зная настоящий вывод терминала.

> Это не «фейковый терминал в промпте»: команда действительно выполняется локально от имени текущего пользователя Windows.

## Что уже есть

- Нативный интерфейс Win32, C++20, без Electron, Python, Node.js или облачного бэкенда.
- Открытие любого веб-чата в обычном браузере (по умолчанию `https://chatgpt.com/`). URL можно поменять.
- Готовый промпт для модели: она понимает, что может запросить действие через RelayBridge и не отвечает «у меня нет терминала».
- Универсальный канал через буфер обмена: работает с любым чат-сайтом и не требует расширения браузера.
- Режим **Watch clipboard**: скопировали ответ модели — команда распознана автоматически.
- Безопасный режим включён по умолчанию: до запуска показывается папка, команда и таймаут; без подтверждения ничего не запускается.
- Команды запускаются только с `cwd` внутри выбранного workspace. Таймаут — от 1 до 900 секунд; дочернее дерево процессов останавливается по таймауту, если Windows позволяет назначить ему Job Object.
- Захват объединённого `stdout`/`stderr`, выходного кода и признака таймаута в сообщении `<relay-result>`.
- Сохранение workspace, URL чата и настроек в `%APPDATA%\RelayBridge\settings.ini`.

## Как пользоваться

1. Соберите или скачайте `RelayBridge.exe` (инструкция ниже) и запустите его.
2. Выберите **Workspace** — корневую папку проекта, с которым разрешено работать.
3. При необходимости укажите URL нужного чата и нажмите **Open chat**.
4. Нажмите **Copy agent prompt** и вставьте весь текст в новый диалог с моделью.
5. Включите **Watch clipboard and accept relay commands**. Оставьте **Ask before every command** включённым, пока не доверяете поведению модели полностью.
6. Когда модели понадобится терминал, она ответит блоком `<relay-command>`. Скопируйте весь её ответ в браузере.
7. RelayBridge предложит подтвердить команду, выполнит её в workspace и скопирует `<relay-result>` в буфер обмена.
8. Вставьте этот результат в чат. Модель сможет разобрать настоящий вывод и сделать следующий шаг.

Если отслеживание буфера выключено, после копирования ответа нажмите **Run command from clipboard** вручную.

## Пример диалога

Модель получает встроенный промпт и отвечает так:

```text
<relay-command>
id: inspect-project
cwd: .
timeout: 60
command: |
  dir /b
</relay-command>
```

После выполнения RelayBridge положит в буфер примерно следующее:

```text
<relay-result>
id: inspect-project
exit_code: 0
timed_out: false
output_truncated: false
output:
CMakeLists.txt
src
README.md
</relay-result>
```

Не нужно писать модели, что команда «наверное выполнилась»: она обязана ждать именно `<relay-result>`.

## Сборка `.exe`

### Через Visual Studio 2022 (проще всего)

1. Установите **Visual Studio 2022 Community** и workload **Desktop development with C++**.
2. Откройте папку проекта через `File → Open → Folder`.
3. Выберите конфигурацию `x64-Release` и соберите проект `RelayBridge`.
4. Готовый файл: `out/build/x64-Release/bin/RelayBridge.exe` (путь в Visual Studio может отличаться).

### Через Developer PowerShell for Visual Studio

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target RelayBridge
.\build\bin\Release\RelayBridge.exe
```

Если ваш генератор Visual Studio кладёт бинарник в другую конфигурационную папку, выполните:

```powershell
Get-ChildItem -Recurse build -Filter RelayBridge.exe
```

### Одной командой с упаковкой

В **Developer PowerShell for Visual Studio 2022** сначала нужно перейти именно в распакованную папку репозитория — не в папку установки Visual Studio. Например, после скачивания ZIP:

```powershell
Set-Location "$env:USERPROFILE\Downloads\ai-agent-in-browser-arena-01a0a084-ai-agent-in-browser"
.\scripts\package-release.ps1
```

Проверьте папку перед запуском: команда `Get-ChildItem scripts` должна показать `package-release.ps1`. Результат будет в `release\RelayBridge.exe` и `release\RelayBridge-windows-x64.zip`.


## Формат команд

Поддерживаются два варианта: XML-подобный блок `<relay-command>…</relay-command>` (рекомендуется) или fenced-блок ```` ```relay-command ````. Поля до `command`:

| Поле | Обязательно | Значение |
|---|---:|---|
| `id` | да | до 64 букв/цифр/`.`, `_`, `-`; идентификатор запроса |
| `cwd` | нет | каталог внутри Workspace; по умолчанию `.` |
| `timeout` | нет | секунды, от 1 до 900; по умолчанию 120 |
| `command` | да | одна команда или многострочный блок после `command: |` |

RelayBridge намеренно использует `cmd.exe`, чтобы `.exe` работал сразу на стандартной Windows. Модель может запускать установленный на компьютере инструментарий (`git`, `cmake`, `cl`, `python`, `npm` и т. п.), если он уже есть в `PATH`.

## Важная безопасность

ИИ и RelayBridge **не являются песочницей**. Даже если `cwd` проверяется, команда, которой вы дали разрешение, работает с правами вашего текущего пользователя и может обратиться к сети, удалить файлы или запустить другие программы.

- Не отключайте подтверждение для незнакомых сайтов, чужих промптов или непроверенных моделей.
- Выбирайте workspace с минимально нужными файлами, не домашний каталог целиком.
- Не запускайте приложение от администратора.
- Проверяйте текст команды в окне подтверждения.
- Ограничение `cwd` — удобная защита от случайной ошибки модели, а не security sandbox.

## Почему буфер, а не скрытый парсинг страницы

Надёжно считывать DOM каждого чат-сайта потребовало бы отдельного расширения и JavaScript, а сайты регулярно меняют разметку и запрещают автоматизацию. Здесь весь рабочий клиент остаётся на C++ и не просит токены, cookie или пароль от ИИ-сервиса. Копирование ответа — прозрачное, универсальное действие; при включённом watch-режиме это один `Ctrl+C`.

## Проверки

Парсер протокола вынесен в переносимую библиотеку и покрыт небольшими тестами:

```bash
# На Linux/macOS можно проверить только переносимый парсер
g++ -std=c++20 -Wall -Wextra -Wpedantic -Isrc src/BridgeProtocol.cpp tests/protocol_tests.cpp -o protocol_tests
./protocol_tests
```

Полный GUI собирается только для Windows.
